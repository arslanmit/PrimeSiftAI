# PrimeSiftAI

PrimeSiftAI is an interactive Jupyter notebook for comparing binary classification models on tabular CSV data. It combines data profiling, preprocessing, model training, hyperparameter tuning, evaluation, and visualization in a single widget-based workflow.

The repository includes a breast cancer dataset as an example, but the notebook can also analyze another compatible CSV file.

## Features

- Load the included breast cancer data or a local CSV file.
- Inspect column types, missing values, summary statistics, and correlations with the target.
- Explore numeric features with a configurable pair plot.
- Compare 17 classification algorithms, including:
  - Logistic Regression, Naive Bayes, KNN, SVM, and Decision Tree
  - Random Forest, Extra Trees, AdaBoost, and Gradient Boosting
  - XGBoost, LightGBM, and CatBoost
  - LDA, QDA, Ridge Classifier, Gaussian Process, and Stacked Generalization
- Apply standard, min-max, robust, max-absolute, normalization, quantile, or power scaling.
- Tune hyperparameters with grid search, randomized search, Bayesian search, or no search.
- Compare default and tuned models using accuracy, precision, recall, F1 score, and ROC AUC.
- Display ROC curves, confusion matrices, and learning curves.
- Append each comparison run to a CSV result file.

## Requirements

- Python 3.10–3.12 recommended
- JupyterLab or Jupyter Notebook

The notebook uses NumPy, pandas, Matplotlib, seaborn, ipywidgets, scikit-learn, XGBoost, LightGBM, scikit-optimize, tqdm, CatBoost, and Dask.

## Local Setup

Using [`uv`](https://docs.astral.sh/uv/) is the quickest option:

```bash
git clone https://github.com/arslanmit/PrimeSiftAI.git
cd PrimeSiftAI

uv venv --python 3.12 .venv
source .venv/bin/activate
uv pip install jupyterlab numpy pandas matplotlib seaborn ipywidgets \
  scikit-learn xgboost lightgbm scikit-optimize tqdm catboost "dask[dataframe]"

jupyter lab AI_Core.ipynb
```

You can also open the notebook directly in Google Colab using the badge at the top of `AI_Core.ipynb`. The notebook contains a package installation step for notebook environments.

## How to Use

1. Open `AI_Core.ipynb`.
2. Run the main notebook cell to display the interactive controls.
3. Select the embedded sample data or enter the path to a compatible CSV file.
4. Choose a hyperparameter search method, scaling method, and one or more models.
5. Adjust the maximum number of numeric columns used in the pair plot.
6. Select optional training logs if detailed output is needed.
7. Click **Run Analysis**.

Running all 17 models with grid, random, or Bayesian search can take considerably longer than selecting a small model subset. For a quick smoke test, choose one or two models and set the search method to `none`.

## Input Data Format

Custom input must be a CSV file containing a column named `target`:

```csv
target,feature_1,feature_2,feature_3
0,1.25,7.10,12
1,2.80,5.45,19
```

The current workflow expects:

- A binary classification target.
- A column named exactly `target`.
- Enough samples from both classes for stratified train/test splitting and cross-validation.
- Features that are compatible with the selected models and preprocessing pipeline.

A column named `diagnosis` is not converted automatically; rename or transform it to `target` before running the analysis.

## Outputs

For a file such as `my_dataset.csv`, PrimeSiftAI appends the model comparison to:

```text
my_dataset_result.csv
```

Each run records default and tuned values for accuracy, precision, recall, F1 score, and AUC, together with the selected search method, scaling method, and a timestamp. The notebook also renders profiling information, a pair plot, model comparison tables, ROC curves, confusion matrices, and learning curves.

## Important Notes

- PrimeSiftAI is an exploratory model-comparison tool, not a production inference service.
- Results depend on dataset quality, class balance, feature design, and validation strategy.
- Metrics produced from the included medical example must not be treated as clinical advice or clinical validation.
- Review data leakage, fairness, calibration, and external validation before using any model in a real decision process.
